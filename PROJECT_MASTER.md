# TDL — единый оперативный план производства

> Версия 1.0 · 12.11.2026. Продуктовые решения: `docs/DECISIONS.md`. Критерии: `docs/TDL_PRODUCT_VISION_AND_ACCEPTANCE.md`. Совместная работа: `docs/AI_COLLABORATION/README.md`.

## 1. Цель

Построить оригинальную коммерчески убедительную dark-fantasy 4X игру The Dead Lords с полноценным 3D поселением и изометрической камерой, связанной экономикой, прогрессией, армиями, persistent world и качественным интерфейсом для mobile и browser/PC.

**Мы производим одну игру, а не набор несвязанных прототипов.** Все подсистемы должны интегрироваться в общую архитектуру, общий серверный state и единый визуальный язык.

## 2. Принятые решения

См. полный перечень в `docs/TDL_PRODUCT_VISION_AND_ACCEPTANCE.md` и актуальный журнал в `docs/DECISIONS.md`.

- Художественный стиль: Premium stylized realism.
- Мир: полноценный 3D, изометрическая камера.
- Ассеты: оригинальные модели + лицензированные материалы + ручная художественная доводка.
- Порядок: один качественный vertical prototype, затем масштабирование.
- Платформы: mobile + browser/PC одновременно.
- Вселенная: оригинальный undead fantasy TDL.

## 5. Технологический proof — обязательный до выбора движка

Сравнить:
1. текущий web client как интеграционная база + 3D rendering option;
2. отдельный web-native 3D prototype (например, Three.js или Babylon.js — кандидат, не решение);
3. Godot с web export — только как отдельный proof, не как предрешённый выбор.

Для всех кандидатов один и тот же тест: сцена земли, Цитадель и 3 здания, изометрическая камера, pan/zoom, выбор/размещение, HUD overlay, resize, touch/pointer. Записать размер загрузки, время до первого usable frame, FPS/frame-time, память/ограничения браузера, качество материалов/света, удобство ассетного конвейера и сложность интеграции с текущим сервером.

Тестировать на одном desktop browser и одном согласованном мобильном профиле. Сравнить не только красивый скриншот, но и реальную интерактивную сцену. Выбор принимает владелец проекта по отчёту с измерениями.

## 6. Качество и Definition of Done

Задача считается завершённой только если:
- реализован конкретный результат из handoff;
- нет подмены работающего функционала концептом или декоративной заглушкой;
- добавлены/обновлены тесты;
- выполнены применимые проверки: `pnpm typecheck`, `pnpm test`, `pnpm check`, `pnpm build`;
- визуальная задача проверена в runtime на согласованных viewport, приложены фактические скриншоты с SHA;
- локализация ru/en не нарушена;
- обновлены профильная документация, handoff, очередь и статус;
- PR прошёл независимый review и CI;
- после merge проверена интегрированная база.

Performance targets из продуктовой спецификации — критерии для измерения, а не заявления о достигнутой производительности.

## 7. Управление работой

Использовать `docs/AI_COLLABORATION/README.md`, `QUEUE.md` и `TASK_TEMPLATE.md`.

- Одна задача — один ответственный агент — одна ветка — один PR.
- ChatGPT координирует и интегрирует; Cloud даёт независимую архитектурную/визуальную проверку; Arena.ai выполняет практические browser/runtime проверки и изолированные прототипы; владелец утверждает продуктовые решения.
- Передача только через handoff в репозитории, не через пересказ чата.
- `main` обновляется принятыми PR, а не прямыми push.
- Никакой агент не начинает зависимую задачу, пока её входные результаты не приняты и не доступны в базовой ветке.
- Запрещены массовая миграция движка, destructive DB/schema изменения, массовая замена ассетов и изменение экономики без отдельного решения.
