# TDL — единый оперативный план производства

> Версия 1.1 · 12.11.2026. Продуктовые решения: `docs/DECISIONS.md`. Критерии: `docs/TDL_PRODUCT_VISION_AND_ACCEPTANCE.md`. Совместная работа: `docs/AI_COLLABORATION/README.md`.

## 1. Цель

Построить оригинальную коммерчески убедительную dark-fantasy 4X игру The Dead Lords с полноценным 3D поселением и изометрической камерой, связанной экономикой, прогрессией, армиями, persistent world и качественным интерфейсом для mobile и browser/PC.

**Мы производим одну игру, а не набор несвязанных прототипов.** Все подсистемы должны интегрироваться в общую архитектуру, общий серверный state и единый визуальный язык.

## 2. Принятые решения

- Художественный стиль: Premium stylized realism.
- Мир: полноценный 3D, изометрическая камера.
- Ассеты: оригинальные модели + лицензированные материалы + ручная художественная доводка.
- Порядок: один качественный vertical prototype, затем масштабирование.
- Платформы: mobile + browser/PC.
- Вселенная: оригинальный undead fantasy TDL.

Подробности и критерии — в продуктовой спецификации и журнале решений.

## 5. Технологический proof — до выбора движка

Сравнить:
1. Сохранение web app как интеграционной базы с добавлением подходящего 3D rendering option.
2. Web-native 3D варианты (например, Three.js и Babylon.js — кандидаты, не решение).
3. Godot с Web export — отдельный кандидат, не предрешённый выбор.

Один тестовый сценарий для всех: terrain, Цитадель и 3 здания, изометрическая камера, pan/zoom, выбор/размещение, HUD overlay, resize, touch/pointer. Измерить размер загрузки, время до usable frame, FPS/frame-time, память и браузерные ограничения, качество материалов/света, pipeline ассетов и интеграцию с сервером.

Тестировать на desktop browser и согласованном мобильном профиле. Выбор принимает владелец по отчёту с измерениями.

## 6. Definition of Done

- Реализован конкретный результат handoff.
- Нет подмены работающего функционала концептом или декоративной заглушкой.
- Добавлены/обновлены тесты.
- Выполнены применимые проверки: `pnpm typecheck`, `pnpm test`, `pnpm check`, `pnpm build`.
- Визуальная задача проверена в runtime на согласованных viewport; приложены фактические screenshots с SHA.
- Не нарушена ru/en локализация.
- Обновлены профильная документация, handoff, очередь и статус.
- PR прошёл независимый review и CI.
- После merge проверена интегрированная база.

Performance targets — критерии будущего измерения, не заявления о достигнутых показателях.

## 7. Модель совместной работы

- ChatGPT: координатор, декомпозиция, спецификации, интеграция, review и статус.
- Cloud: независимая архитектурная и визуальная экспертиза, анализ технологий и review.
- Arena.ai: реальный запуск проекта, browser QA, скриншоты и изолированные прототипы.
- Владелец: продуктовые решения и окончательная приёмка.
- GitHub — общая память и handoff. У каждого агента своя ветка и PR. `main` — только принятые изменения.
- Прямой канал ChatGPT↔Cloud/Arena не предполагается: координатор выдаёт им точные ссылки и задания, владелец переносит handoff в соответствующий чат, агенты возвращают результат в GitHub.

## 8. Ближайшие действия

1. Проверить CI PR #9 на новой базе после merge PR #11; выполнить независимый review большого diff.
2. Cloud выполняет TDL-3D-001: сравнение технологий, без production-кода.

4. ChatGPT сводит отчёты и готовит изолированный benchmark только после технологического и продуктового gate.
5. Cloud + ChatGPT готовят visual benchmark и asset bible; владелец принимает визуальный стандарт.
6. После принятия технологии и визуала реализуется vertical prototype; затем функциональный loop.
7. Только после успешной приёмки вертикального среза начинается масштабирование.

**Не начинать большую фазу ради активности. Начинать её, когда предыдущая прошла свой gate.**
