# Актуальные решения и правила совместной разработки (12.11.2026)

**Этот блок имеет приоритет над противоречащими ему историческими инструкциями ниже.** Перед работой прочитать `docs/AI_COLLABORATION/README.md`, `docs/AI_COLLABORATION/STATUS.md`, `PROJECT_MASTER.md`, `docs/DECISIONS.md` и `docs/TDL_PRODUCT_VISION_AND_ACCEPTANCE.md`.

- Цель TDL утверждена: Premium stylized realism, полноценный 3D-мир с изометрической камерой, оригинальная undead-fantasy идентичность, mobile + browser/PC. Это целевая спецификация, не заявление о готовой реализации.
- Текущий PixiJS/React клиент — существующая база. Старые правила Pixi описывают текущую реализацию, но не запрещают исследовательский 3D-прототип. Движок не выбран; массовая миграция запрещена до сравнительного прототипа и отдельного решения владельца.
- Cloud, Arena.ai и ChatGPT работают через GitHub handoff, отдельные ветки и PR. Никаких прямых коммитов в `main`, force-push или параллельного редактирования одних файлов. Полный процесс — `docs/AI_COLLABORATION/README.md`.
- `main` обновляется только принятыми PR после review и CI. После merge обновить `PROJECT_MASTER.md`, очередь и `docs/AI_COLLABORATION/STATUS.md`.
- Не заявлять о запуске, FPS, мобильной совместимости, скриншотах или CI без проверяемого доказательства и commit SHA.
- Утверждённые цели не дают разрешения на массовый рефакторинг, смену движка, изменение экономики, протокола, схемы БД или production-инфраструктуры.

# AGENTS.md

## Язык

Всегда отвечать пользователю **по-русски** (коммит-сообщения — по-русски).

## Проект

**Мёртвые лорды / The Dead Lords (TDL)** — браузерная стратегия (жанр RoK),
зомби-лорд замка. **Не Telegram-бот и не связан с Telegram**; название репозитория `tg_bot` — историческое. TypeScript-монорепо (pnpm + Turborepo): один серверный процесс
отдаёт API, WebSocket и клиент.

- Документация: `docs/README.md` — входная точка: карта, статусы, процесс работы.
  Журнал решений — `docs/DECISIONS.md`, состояние — `docs/STATUS.md`.
  Старые документы — `docs/archive/game/`, разбираются по темам (см. `docs/README.md`).
- Состояние работы: `docs/STATUS.md`. Корневой `STATUS.md` — указатель; старая версия в `docs/archive/root/STATUS.md`.
- Текущая реализация клиента: PixiJS для сцены, React для HUD; это baseline, не окончательно утверждённая технология целевого 3D-мира. План: [PROJECT_MASTER.md](PROJECT_MASTER.md).
- Разбор open-source решений и референсы: [docs/design/client-stack.md](docs/design/client-stack.md) §4.

## Команды

```bash
cp .env.example .env      # адрес базы, порт, секрет сессий
pnpm dev:db               # местный Postgres на 55432 (первый раз — инициализация)
pnpm dev                  # мир: API, сокет и клиент через Vite (PORT из .env)
pnpm db:reset             # снести схему базы разработки и поднять мир заново
```

Проверки (обязательны на каждом этапе, перед коммитом):
`pnpm typecheck`, `pnpm test`, `pnpm check`, `pnpm build`.
`pnpm check` = реестр + границы пакетов + i18n (ru/en паритет) + календарь сборки.
Снимки: `pnpm shots`, иконки из AI-листа: `pnpm icons`.
Запуск в Replit: `.replit` → `bash tools/replit-dev.sh` (поднимает dev-базу и сервер,
превью на локальном порту 3000).

Тесты идут на настоящем Postgres: каждый пакет сносит схему своей тестовой базы
`tdl_test_<пакет>` и не трогает рабочую (`tdl`). Адрес — `TDL_TEST_DB_URL`
(имя базы обязано содержать `test`).

## Текущая архитектура клиента (baseline; исторические PixiJS-правила до выбора 3D runtime)

```
apps/client/src/
├── game/   — PixiJS. НЕ импортирует React. НЕ использует хуки. Чистый TS.
├── ui/     — React + Tailwind (World, Hud, панели). НЕ импортирует Pixi.
├── shell/  — хроника, первый запуск, формы (React).
├── i18n/   — словарь ru/en (паритет проверяется `pnpm check`).
├── net.ts  — транспорт @tdl/protocol (WS). Только транспорт.
└── styles.css / hud.css — глобальные стили и стили HUD.
```

- **ЕДИНСТВЕННАЯ точка связи** Pixi ↔ React — `src/game/bridge.ts` (EventTarget).
  Никаких прямых вызовов методов между `game/` и `ui/`.
- HUD — `src/ui/` + `hud.css` (единый источник правды). Визуальный дизайн UI
  согласуется с заказчиком по процессу «разбор → скелет → варианты → выбор»
  (этап 2.5, [docs/plan/roadmap.md](docs/plan/roadmap.md)).
  Палитра для canvas/спрайтов — из палитры дизайна (`hud.css` / дизайн-документ).

### Правила Pixi (src/game/)

- Цикл — только `app.ticker.add(...)`.
- При глубине — `sortableChildren = true`, `zIndex = worldX + worldZ`.
- Диметрия: клетка 71.4×41.4 (≈1.72:1), формулы — `game/court/isometric.ts` (с тестами).
- Ассеты — только `PIXI.Assets`. НЕ `new Image()`, НЕ `<img>` под сцену.
- Статичные контейнеры — `cacheAsTexture()`.
- Слои: фон → тайлы → здания → эффекты.

### Правила HUD (src/ui/ + hud.css)

- Tailwind-классы; без inline-стилей, кроме динамики (позиции, прогрессы).
- `#hud-root { pointer-events: none }`, панели — `pointer-events: auto` —
  клики по пустому месту должны проходить в Pixi.
- Данные — только через `bridge.on(...)` / существующий `store.ts`.
- Игровые тайлы/здания НЕ рендерить в React.
- Не хранить игровое состояние в React-state дольше, чем нужно для отрисовки.

### Правила протокола

- `packages/protocol` (`@tdl/protocol`), сервер и БД — **НЕ МЕНЯТЬ** без явного
  разрешения заказчика.
- Типы — из `@tdl/protocol`, не дублировать.
- Игрок — зомби-лорд; клиент ничего не считает сам: числа приходят снимком и патчем.

### Тексты (i18n)

- Любой новый ключ — сразу в `ru` и `en` (`apps/client/src/i18n/shell.ts`),
  иначе `pnpm check` падает. Ирония — в голосе хрониста, не в имени ресурса и не в кнопке.

## Запрещено

- Добавлять production 3D runtime (`three`, `@react-three/*`, Godot Web или иной) в основной клиент до сравнительного прототипа и отдельного решения владельца. Изолированные исследовательские прототипы разрешены в рамках назначенной задачи.
- Смешивать Pixi и React в одном файле.
- Прямые вызовы методов между `game/` и `ui/` (только bridge).
- Хардкодить цвета — CSS-переменные палитры из `hud.css` / дизайн-документа.
- Добавлять npm-зависимости без согласования с заказчиком.
- Тронуть рабочую базу `tdl` из тестов.

## При добавлении нового экрана/сцены

1. Для изменений существующей Pixi-сцены: класс в `game/<scene>/<Name>Scene.ts` (Pixi, без React). Новый 3D runtime не добавлять до отдельного решения по итогам prototype gate.
2. HUD-компоненты — `ui/` (зоны HUD — в рамках согласованного с заказчиком дизайна).
3. Связь — только через `bridge.ts` (новые события объявить в bridge).
4. Unit-тесты на математику (координаты, глубина, границы).
5. Словарь ru/en для всех новых текстов.

## Дисциплина этапов (чекпоинты)

Работа идёт по этапам плана [roadmap.md](docs/plan/roadmap.md).
Каждый этап завершается:

1. Все проверки зелёные: `pnpm typecheck && pnpm test && pnpm check && pnpm build`.
2. Критерий приёмки этапа выполнен.
3. Коммит (по этапам, по-русски) + push на ветку сессии.
4. Статус в плане (таблица §Статус) и в `STATUS.md` — `сделано → проверено`,
   заказчику — что тестировать в Replit.
5. Следующую READY-задачу можно начинать после выполнения зависимостей и CI; отдельное одобрение владельца обязательно для продуктовых решений и изменений с повышенным риском.

Не торопиться. Если шаг неоднозначен — сначала уточнить у заказчика.

## Правило взаимодействия с заказчиком: сначала ответ, потом действие

- Сообщения с пересланным ТЗ, советом другого ИИ, предложением, цитатой или контекстом сами по себе не считать поручением на реализацию.
- Сначала ответить заказчику по существу и подтвердить, как понято его сообщение. Не запускать инструменты, не менять код и не начинать долгую проверку, пока заказчик явно не попросил об этом либо намерение недвусмысленно не следует из формулировки.
- Если намерение можно понять по-разному, задать один короткий уточняющий вопрос и дождаться ответа; не считать концепт выбранным или утверждённым по рекомендации третьей стороны.
- Выполнять подтверждённую работу последовательно и ограниченными шагами. Коммит и пуш — после каждой правки в активной разработке, в ветку сессии, без `--force`.

## Сдача результата: через PR, CI и воспроизводимые доказательства

- Заказчик не открывает превью агента (`start_process`, `get_process_output`) и не видит его. Превью **не** считается сдачей результата; не писать «смотрите превью».
- Заказчик получает результат через PR и интегрированный `main`. Replit может использоваться как одна из сред проверки, но не является единственным способом сдачи. Указывать точный commit SHA, сценарий, viewport и ссылки на фактические артефакты.
- Локальный запуск допустим только для собственной проверки (`tsc`, `curl`) и не передаётся заказчику как ссылка.
- Коммиты — в отдельную ветку исполнителя; PR — в согласованную базовую ветку. Добавлять только файлы своей задачи, без `git add -A` и без чужих изменений рабочей копии.
- Для проверки интерфейса не добавлять второй сервер и не трогать базу без отдельного согласования. Статичная страница прототипа живёт на том же dev-сервере, что и игра (`pnpm dev` / `tools/replit-dev.sh`).
- Прототипы и макеты, которые заказчик должен проверить, открываются **кнопкой внутри игры** (переключатель). Не просить заказчика вводить адрес или ссылку вручную.
