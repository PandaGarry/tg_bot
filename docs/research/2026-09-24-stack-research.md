## 3. Рекомендация (черновик для обсуждения)

**Клиент:** Cocos Creator 3.8+ (TypeScript). `web-mobile` сборка → Telegram Mini App (есть официальное
расширение cocos-telegram-miniapps), нативные сборки → App Store / Google Play. Тот же движок, что у slgclient.

**Язык:** TypeScript везде. Для соло-разработки один язык + общий пакет правил (клиент, сервер, тесты).

**Сервер — основной вариант:** SpacetimeDB 2.x, TS-модуль. Один database на всё, `world_id` на каждой сущности
(королевство и KvK — просто разные world_id, переезд = транзакционный UPDATE). Референс — BitCraftPublic.
Снимает: ORM/схему, WebSocket-сервер, дельта-синхронизацию, персистентный планировщик таймеров.
Риски: BSL (один инстанс в проде), молодой TS-рантайм, дизайн подписок по чанкам, SDK в нативном Cocos.

**Сервер — запасной вариант:** Node + Postgres + Redis, «world-actor»: процесс владеет N мирами, каждый мир —
однопоточный цикл, write-behind, персистентная очередь событий. Тот же пакет правил.

**Решение через спайк (~2 недели):** карта 1200×1200 чанками, 5 000 фейковых городов, 500 ботов,
марши с событиями прибытия, город с 3 зданиями и ленивыми ресурсами. Мерить: латентность подписки на чанк,
память, загрузку в Telegram WebView (iOS/Android), нативную сборку Cocos с SDK.

## 4. Правила проектирования «под KvK с первого дня»

1. `world_id` на каждой мировой сущности; `player_id` глобален; членство игрока в мире — данные, не топология.
2. Один писатель на мир (транзакция редьюсера / цикл актора). Между мирами — только сообщения и миграции.
3. Марш = (from, to, depart_at, arrive_at); позиция считается на клиенте; сервер обрабатывает только событие прибытия.
4. Ресурсы лениво: `amount(t) = min(cap, stored + rate·(t − last_ts))`. Никаких тиков производства.
5. Карта чанками (32×32); подписки/пуши по чанкам; туман — таблицы видимости по игроку/альянсу.
6. Правила — чистые функции над plain-data в `packages/rules`, 100% под тестами; сервер тонкий.
7. Аккаунт с привязками провайдеров (telegram, apple, google) с первого дня.
8. Бой v1 — мгновенное разрешение по прибытии (стиль GoT: Conquest); непрерывные полевые бои RoK — позже.

## 5. Что откуда брать

- BitCraftPublic (Apache-2.0): структура модуля, регионы, клеймы, scheduled reducers — можно копировать.
- TravianZ / Pillage First: кривые стоимости/времени, производство, боевая формула — только формулы.
- Solaris: марши с ETA, отчёты, дипломатия альянсов — только паттерны.
- slgserver / slgclient: список фич, форма протокола, приёмы карты/тумана в Cocos — только чтение.
- OGameX (MIT): организация очередей/миссий и тестов — можно копировать.

## 5. Что изменилось после обсуждения (24.09.2026)

Вводные пересмотрены пользователем:

- **Telegram Mini App исключён.** Цель — самостоятельное мобильное приложение в браузере
  телефона (как RoK/GoT: Conquest), дальше — нативная обёртка. Всё, что было связано с TMA
  (расширение Cocos, Stars, бот как канал удержания), из плана убрано.
- **Нужен MVP прямо сейчас**, а не сравнение стеков: стек, лор и механики выбраны исполнителем.
- Язык по-прежнему один на всё, ставка на «не писать инфраструктуру руками».

Итоговый выбор для MVP (реализован в этом репозитории):

| Слой | Выбор | Обоснование |
|---|---|---|
| Клиент | Vite + TypeScript + Canvas 2D, mobile-first | 47 КБ JS, мгновенный старт на телефоне, полный контроль над картой. Cocos Creator остаётся вариантом для нативной сборки, но игра от движка не зависит. |
| Сервер | Node 22 + `node:sqlite`, один процесс | ноль внешних сервисов; `world_id` на сущностях, один писатель на мир, события с временем вместо тиков |
| Правила | `packages/rules` (чистые функции + тесты) | формулы работают и на сервере, и на клиенте |

Отложено до спайка: SpacetimeDB (BSL, один инстанс в проде), Nakama (для сторов: IAP и
социалка), Postgres (если упрёмся в SQLite).
