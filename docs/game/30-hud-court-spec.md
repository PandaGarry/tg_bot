## 0. Объём и термины

- **Двор** — территория/сцена замка игрока в конкретном мире (канон — [04-systems.md](04-systems.md)).
- **Цитадель** — центральное здание двора. «Ратуша»/`townhall` в коде — устаревшее имя той же сущности; переименование — отдельная задача (см. §6).
- **HUD** — неподвижный интерфейсный слой поверх сцены (React, `src/ui/` + `hud.css`). Сцена (Pixi, `src/game/`) рисует двор; HUD рисует панели, чипы, док.
- В объёме этого ТЗ: **весь главный экран «Двор»** как оболочка — профиль, ресурсы, премиум-валюта, меню, док, боковые панели, чат, сцена. HUD карты, марша, боя и отчёта — отдельные спецификации после шага 5 плана.

## 1. Архитектурные правила (обязательны для любой зоны)

Поток данных один и не меняется от выбора skin:

```
сервер (модули + ядро)
  → снимок view / патч patch (@tdl/protocol)
  → store.ts (ClientState)
  → HUD (React) — только отображение
  → команда send(commandId, payload) → сервер
```

- HUD **не считает игровые числа сам**: ресурсы, уровни, сила, таймеры приходят в `view`/`patch`; клиент лишь отображает их и считает остаток таймера от `serverNow`/`clockOffset`.
- Любое действие игрока — команда протокола (`court.*`). Локальной мутации состояния нет.
- Связь сцены и HUD — только `game/bridge.ts` (события, §4). Прямых вызовов между `game/` и `ui/` нет.
- Демонстрационные/мок-числа допустимы **только в изолированном preview макетов** (режим `МАКЕТЫ`), никогда — в основной игре.
- Все тексты — ключами i18n, сразу ru и en (`pnpm check` проверяет паритет).
- Если для зоны нет данных в протоколе — зона не выдумывает их, а попадает в список расширений (§6) и до реализации показывает честное состояние («закрыто», «скоро», пусто).

### E. Правая колонка / контекстные панели

- **Панель строительства** (открывается из дока или кнопки «Строить»): каталог `CATALOG` по вкладкам экономика/войско/декор; у каждой карточки — цена (`cost`) и требование по уровню Цитадели (`th`); закрытые показаны с замком. Данные: состав каталога сейчас продублирован в клиенте (`BuildPanel.tsx`) — ⚠ расширение: каталог должен приезжать с сервера (или из protocol), чтобы цена/требования не разъезжались.
- **Панель очередей** (деталь к пилюлям сцены): список активных таймеров стройки/улучшения с остатком, кнопки «ускорить»/«отменить». ⚠ расширение: сейчас `court.upgrade` и `court.place` мгновенные, дедлайнов стройки в view нет — это крупнейший недостающий блок (шаг 4 плана: «таймер стройки живёт после рестарта»).
- **Сворачивание**: правая колонка сворачивается, чтобы не закрывать сцену (решение круга 3, [ui/hud/README.md](ui/hud/README.md)).

### F. Слой сцены (не HUD, но контракт интерфейса)

Пилюли очередей над зданиями, призрак размещения, сетка, выноска выбора здания рисует **Pixi-сцена**, не React. HUD передаёт сцене намерения через `hud:action`, получает клики через `building:click`/`tile:click`. Пилюлям нужны дедлайны из view — то же ⚠ расширение очередей.

### G. Системные состояния

| Состояние | Данные | Что видит игрок |
|---|---|---|
| Подключение | `store.status`: offline/connecting/online | ненавязчивый индикатор; при offline — панель не врёт о «живых» числах |
| Первый вход во двор | `modules.court.starter = 0` | приветствие и команда `court.enter` (стартовые ресурсы уже реализованы) |
| Отказ сервера | `store.errors` (ключ + params) | человекочитаемый текст по ключу i18n; служебных слов нет |
| Отчёт | `store.reports` | строки отчёта (например, `court.report.upgraded`) |
| Рассинхрон версии протокола | `ready.protocolVersion`, отказ ворот | предложение обновить страницу |

### H. Чат (зона не размещена, §8.2)

Требования заказчика: как в аналогичных играх. Игрок видит чат постоянно в свёрнутом виде с числом непрочитанных, раскрывает его в панель. Чат не закрывает сцену и кнопки дока; на узком ландшафте в свёрнутом виде занимает одну полосу.

Варианты размещения (выбирает заказчик):
- **(a)** свёрнутая полоса слева внизу над доком, раскрывается вверх. Так в RoK — см. [25](25-court-layout.md) §1. Предложение автора, решение за заказчиком.
- **(b)** правая колонка под панелями, ниже «Почты».
- **(c)** отдельная ячейка дока с полноэкранной панелью. Дешевле по месту, но чат не виден постоянно.

Данные: в протоколе чата нет — ⚠ расширение. Чат идёт отдельным каналом, не через очередь писателя мира ([05-architecture.md](05-architecture.md)). Реализация — отдельный согласованный шаг, в этап 1 не входит.

## 3. Состояния и сценарии взаимодействия

1. **Покой (idle):** виден двор, все зоны HUD на месте, ничего не модально.
2. **Выбор здания:** `building:click` → выноска/панель здания (уровень, действия: улучшить, переместить, убрать). Команды: `court.upgrade` (Цитадель), `court.move`, `court.remove`.
3. **Размещение:** панель строительства → карточка → `hud:action {action:"place", ...}` → сцена показывает призрак (`scene:mode.placing`) → тап по клетке (`tile:click`) → подтверждение → `court.place {type,x,z}`. Отказ сервера — призрак снимается, показывается ключ ошибки.
4. **Перемещение (включая дороги):** выбран объект → «переместить» → призрак с `from` → `court.move {type,fromX,fromZ,toX,toZ}`; дорога — `court.road {x,z,moveFrom}`. Все размещаемые элементы перемещаемы (канон).
5. **Дорожный инструмент:** `hud:action {action:"road"}` → `scene:mode.roadTool` → тапы ставят/снимают плиты (`court.road {x,z,remove?}`).
6. **Стройка с таймером (цель):** после реализации очередей (§6.1) — пилюля в сцене + строка в панели очередей; остаток считается от `serverNow`, переживает перезагрузку вкладки.

Эфемерный режим (`CourtSceneMode`) — только клиентская подсказка: он не авторитетен и не уходит на сервер.

## 4. Контракт bridge (существующие события)

| Событие | Направление |_payload_ |
|---|---|---|
| `state:update` | store → сцена/HUD | `{court: CourtState}` из view/patch |
| `scene:mode` | HUD → сцена | `{active, placing, roadTool, pending}` |
| `hud:action` | HUD → сцена/транспорт | `{action, payload}` → команда протокола |
| `tile:click` | сцена → HUD | клетка `{x,z}` |
| `building:click` | сцена → HUD | `{x,z,id,type}` |
| `camera:moved` | сцена → HUD | `{x,y,zoom}` (для компаса/координат, если появятся) |

Новые события добавляются только в bridge и только парой «сценарий → событие».

## 5. Адаптивность и доступность

- Ориентация: **ландшафт** (решение круга 4). Проверочные ширины: 390 / 768 / 1280 (и высота <500 — «низкий ландшафт»).
- HUD — фиксированный слой: **не масштабируется вместе с зумом сцены** (решение круга 5).
- `#hud-root { pointer-events: none }`, панели — `auto`: пустые места пропускают жесты в Pixi.
- Цель касания ≥44 px; `100dvh`, без двойного тап-зума (`touch-action: manipulation`).
- Бейджей внимания одновременно 3–5; цифры сокращаются (K/M/B), точное — в один тап.
- Ярусы плотностей (<389 / база / 431–767 / ≥768) уже описаны в архивной части STATUS и hud.css — сохраняются как система, конкретные значения сверяются при реализации skin.
