# Модули

Этот файл читается перед разработкой любого модуля. Архитектурное решение — [05-architecture.md](05-architecture.md). Здесь только порядок работы.

## Правило

Модуль не запускает себя. Он объявляет обработчики и возвращает эффекты. Ядро вызывает обработчик и применяет эффекты одной транзакцией.

Модуль обеспечивает свои таблицы, тексты, проверки и экран. Он не обеспечивает часы, склад и рассылку. Это ядро.

## Классы

Мировой модуль — двор, карта, бой, столица, событие по дате. Его вызывает писатель мира.

Модуль ворот — регистрация и сессия. Его вызывает вход. Писатель мира его не знает.

Модуль вида — панель и слой карты. Его монтирует оболочка, когда гнездо видно.

Один каталог может содержать мировой код и вид. Ворота в этот каталог не кладутся.

## Добавить модуль

1. Прочитать этот файл.
2. Создать `packages/modules/<id>/module.ts`. `id` — постоянный, латинский, через дефис.
3. Заполнить `defineModule`. Версия с 1.
4. Если нужна таблица — схема в этом модуле и миграция в этом модуле. Ключ каждой строки содержит `world_id`.
5. Тексты `ru` и `en` на каждый ключ, который видит игрок.
6. Прогнать сборку реестра. Она обновляет `registry.gen.ts`.
7. Тест: обработчик на фиксированных данных возвращает ожидаемые эффекты. Без базы и без браузера.
8. Включить модуль в конфигурации миров, которым он нужен.

Ядро, хост и чужие модули в этом шаге не редактируются. Если без правки ядра фича не встаёт, это отдельное решение по [05-architecture.md](05-architecture.md), не часть задачи модуля.

Выключить из сборки — удалить каталог и собрать реестр заново. На существующих мирах перед этим состояние `disabled`, затем архивная миграция, если строки больше не нужны.

## Контракт

```ts
defineModule({
  id: "capital",
  version: 1,
  depends: ["map", "clan"],
  content: {
    strings: { ru: {}, en: {} },
  },
  rules: {
    modifiers: [],
    resolvers: [],
    schedules: [],
  },
  server: {
    commands: [],
    tables: [],
  },
  client: {
    slots: [],
    mapLayers: [],
  },
})
```

`depends` задаёт порядок загрузки и требование присутствия. Это не разрешение импортировать чужой код.

Сборка отвергает модуль, если:

- `id` занят
- зависимость отсутствует
- ключ есть только в одном языке
- гнездо не из списка оболочки
- два модификатора одной фазы заявили один приоритет
- модуль импортирует другой модуль

Пустые списки можно не писать.

## Что можно объявить

Ресурсы, здания, узлы карты, типы войск, узлы исследований, строки.

Модификатор: фаза, приоритет, функция. Фазы ядра: производство, предел, цена, скорость марша, удар, защита, скорость стройки, сбор. Новой фазы у модуля нет.

Резолвер боя, сбора или обучения. Добыча — запись резолвера, не условие в чужом файле.

Команда: id, схема входа, проверка, обработчик.

Гнездо: `boot.language`, `boot.slides`, `creation.steps`, `hud.resources`, `nav.primary`, `court.view`, `map.layers`, `report.rows`, `lord.panel`, `sheet`.

## Эффекты

Обработчик получает снимок, который собрало ядро. Чужие таблицы он не читает. Возвращает только:

- дельты склада
- поставить срок или снять срок
- событие для журнала
- операции патча
- ошибку ключом

Срок содержит `id`, `world_id`, `owner`, `wake_at`, ключ идемпотентности. `owner` равен `id` модуля.

Ядро пишет эффекты. Модуль, открывший соединение с базой, сделан неправильно.

## Когда ядро вызывает

Команда с id этого модуля, и модуль `enabled`.

Либо срок с этим `owner`, `wake_at <= now`, модуль `enabled`.

Иных вызовов нет. Цикла модуля нет. `setInterval` в модуле запрещён.

Событие через неделю: в день постановки обработчик возвращает срок. До даты вызовов нет. В дату ядро вызывает `onDeadline`. Если процесс был выключен, вызов происходит на первом проходе после старта. Ключ идемпотентности не даёт провести срок дважды.

## Выключатель

На каждый мир: `enabled` или `disabled`.

`disabled`: команды получают `module.disabled`. Сроки этого владельца выборка не возвращает. Код может оставаться в сборке. Память под тихий включённый модуль допустима. Память не повод вызывать его заранее.

Включение модуля, которого нет в `registry.gen.ts`, отклоняется. После включения просроченные сроки проводятся один раз каждый.

Регистрация выключается флагом ворот, не флагом мира. Мировой писатель этот флаг не читает.

## Данные

Таблица модуля принадлежит модулю. Другой модуль и ядро пишут в неё только через эффекты, не прямым запросом из чужого кода.

Склад общий. Ресурс в нём появляется, потому что модуль объявил `resource_id`. Отдельной колонки `meat` в ядре нет. Предел грибов — свойство ресурса, которое объявляет модуль двора.

Миграции вперёд только. Версия модуля хранится на мире. Хост применяет недостающие миграции до открытия мира.

## Сезон, а не удаление

Обычный способ остановить модуль — `disabled` на мир. Каталог остаётся. Реестр не пересобирается. Ядро модуль не вызывает, его модификаторы не входят в расчёт, его сроки выборка не берёт.

Хеллоуин так и живёт: в сборке круглый год, включён на свою неделю, затем сам возвращает эффект выключения. Следующий сезон — снова `enabled`. Награда сезона должна быть модификатором со сроком или явной выдачей в момент события. Нельзя записывать вечный бонус в склад и считать, что выключение его отменит.

Удаление каталога — только если кода не должно остаться в сборке. Для прошедшего события это не используется.

## Сбор

Точка хранит запас. Уровень задаёт запас в данных, не в ядре. На точке один марш.

В момент занятия ядро записывает скорость, начало, остаток точки и конец. Собрано в любой момент = скорость × прошедшее время, но не больше остатка и не больше груза. Эти поля игроку не показываются.

Обработчик модуля не возвращает сумму сбора. Если вернул число и оно не совпало с расчётом по времени, ядро число выбрасывает, игроку начисляет расчёт, админу пишет расхождение. Игрок видит обычный отчёт: сколько древесины пришло в замок.

Чужой бой за точку останавливает сбор на времени боя. Домой уходит уже собранное. Точка теряет ровно это число. Напавший теряет убитыми, защитник — ранеными.

Новая сборка не переписывает скорость уже стоящего марша.

## Запрещено

- Импорт другого модуля.
- Свой таймер, свой пул базы, своя рассылка всем игрокам мира.
- Запись склада мимо эффекта.
- Имя чужого модуля в коде ядра.
- Текст игрока без ключа.
- Боевой расчёт в React.
- Выключение модуля удалением строк в обход миграции.

## Проверка фундамента

`packages/modules/_probe` объявляет ресурс и модификатор производства. Ядро и боевые модули не правятся. После сборки ресурс виден в складе, бонус виден в числе. После удаления каталога и пересборки реестра новые миры этого ресурса не имеют. Старые миры не падают: пробная миграция в боевую сборку не входит.

Пока эта проверка не зелёная, игровые модули не пишутся. Иначе первый ресурс останется особым случаем ядра.
