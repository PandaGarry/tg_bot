и не устраивает. Ядро (сервер, модули, календарь, протокол) хорошее — оставляем. Ищем

## Ответ на вопросы заказчика (дополнение 08.10.2026)

### Xnova (просят «посмотреть, говорят хороший фронтенд, хорошо работает с бэкендом»)

На GitHub под именем Xnova — браузерные OGame-клоны (PHP). Смотрел двух активных:

| Репозиторий | Стек | Суть фронтенда |
|---|---|---|
| [alexprowars/xnova](https://github.com/alexprowars/xnova) (MIT, активен, пуш 03.10.2026) | Laravel + **Vue 3 (Inertia) + Tailwind 4 + Vite**, Reverb (WebSocket, pusher-js), **Rust-движок боя через FFI** (`rust/battle_engine_ffi`), phpstan, phpunit | Сервер-драйвен SPA: Laravel отдаёт props, Vue рендерит страницы. «Галактика» — **DOM-таблицы + CSS** (классический OGame-вьюпорт: ряды планет в `<table>`, тёмная тема на CSS-переменных). Canvas — только графики. Сцены-карты нет, двора нет — планета = страницы управления (здания списком, таблица исследований) |
| [ultimateXnova/ultimateXnova](https://github.com/ultimateXnova/ultimateXnova) (AGPL-3.0) | PHP + server-rendered страницы, `styles/` + `scripts/` | Классический 2000-е браузерный OGame с «осовремененным» UI. Архитектура сервер-рендер, не SPA |

Вывод: «хороший фронтенд» Xnova — это **аккуратный DOM-UI (Vue + Tailwind + CSS-переменные) и живое realtime (Reverb)**. Для нашей сцены двора/карты это **не даёт ничего** — у них нет ни canvas, ни изометрии, ни двора. Для TDL полезно заимствовать три вещи:
1. **Рust-движок боя через FFI** — когда дойдём до шага боёв/маршей, тяжёлые расчёты можно вынести в Rust (как у них) вместо «на лету» на Node;
2. **AGENTS.md в репозитории** — у них есть (и русским); нам стоит завести такой же, чтобы агентская разработка шла по одним правилам;
3. Подтверждение, что паттерн «сервер = единственный источник правды, клиент = тонкий рендерер + realtime» — индустриальный стандарт жанра. У нас он уже есть (`@tdl/protocol`).

Переносить Vue/Inertia/Laravel в TDL **не нужно**: React + Tailwind + WS-протокол у нас уже та же архитектура, и она живая.

### @pmndrs/uikit (вопрос «может, неплохой вариант для UI»)

[pmndrs/uikit](https://github.com/pmndrs/uikit) (3 247⭐, MIT, активен) — это **3D-интерфейсы внутри three.js-сцены**: flexbox через yoga-layout в 3D, MSDF-шрифты, кнопки/панели, живущие в сцене R3F. То есть это часть того же 3D-экосистема, от которого уходим. Для 2D-пути (PixiJS + React HUD) он не применяется: весь HUD TDL остаётся в React/Tailwind (это и есть «UI-кит» — существующий `hud.css` + компоненты). Если бы 3D оставался — был бы кандидат на HUD в сцене.

### «Тебе подвластны ли Godot или Unity?»

Честный ответ — **для этого проекта нет, и вот почему**:

| | Unity | Godot 4 |
|---|---|---|
| Open-source | Нет (проприетарный) | Да (MIT) |
| Веб-сборка | Только платный тариф Pro (с 2024) | Да, бесплатно (WebAssembly) |
| Могу ли я писать код | C# скрипты — да | GDScript/C#/.tscn (текст) — да |
| Могу ли я **запустить и проверить** в этой среде | **Нет**: редактор Unity не поднять (бинарники не скачиваемы отсюда, лицензия, GUI-редактор). Разработка вслепую | **Нет**: без редактора Godot нельзя собрать web-экспорт и не видно сцены. Headless-запуск тоже требует бинарника, которого в этой среде нет |
| Цена для TDL | Смена всего: C#, редактор-сцены, платный веб, смерть React/Tailwind/hud.css/shots | Смена всего: GDScript/C#, смерть React/Tailwind/TS-тулчейна/shots; изометрический тайлмап встроен, но писать сцены вслепую долго |

Вывод: сценарий «агент пишет, человек смотрит в предпросмотре, `pnpm test/shots` в зелёном» для Unity/Godot в этой среде не выполняется. **PixiJS — тот же сценарий целиком**: пишу TS, запускаю, снимаю `pnpm shots`, тестирую, ты видишь в предпросмотре.

## Рекомендация

**Сцена (двор, потом карта) — PixiJS 8 (MIT, v8.22, TypeScript). HUD — React 19 + Tailwind.
Протокол — `@tdl/protocol`. Всё остальное (shots, icons, store, i18n) — как есть.**

Почему PixiJS, а не Phaser:

- PixiJS — рендерер, а не хозяин экрана: React остаётся хозяином HUD, `hud.css` не трогаем,
  сцены просто живут в `<canvas>` внутри React-разметки.
- Для двора 14×14 и карты не нужны физика/сцены/ТМХ-обвязка — это лишний вес и бюрократия
  «для меня и для тебя».
- Solaris — живое доказательство масштаба: 4X на PixiJS + Node работает в продакшене.
- PixiJS 8 покрывает то, что было в 3D-дворе и надо оставить: спрайты, глубина (z-order по
  диметрии), пан/зум (Camera), фильтры/blend-режимы для ночи (свет как слой поверх дня —
  по [22](22-seasons-daytime-buildings.md)), частицы (pixi-particle-emitter) для эффектов.

Почему не готовая игра целиком: чужой стек и чужой протокол дороже, чем писать сцену
спрайтов поверх готового прототипа `ui/court/index.html`, где уже решены
клетка↔мир, глубина, камера и сценарии стройки.

## План прилётки (спайк, чтобы сравнить со шлаком вживую)

1. В `@tdl/client`: убрать `three`, `@react-three/fiber`, `@types/three`; добавить `pixi.js`.
   Приложение `court3d` отцепить (не трогать main).
2. `src/court/PixiCourt.tsx`: canvas внутри текущей разметки. Диметрическая сетка 14×14
   (формулы — из прототипа `ui/court/index.html`), здания — спрайты из существующих PNG
   (конвейер `pnpm icons`), сортировка по глубине, пан/зум, призрак в стройке, выбор.
   Данные — из того же view/патчей, что сейчас (сервер не трогаем).
3. Связь HUD↔сцена — через существующий `store.ts` (BuildPanel уже пишет в store).
4. `pnpm shots` должен продолжать снимать страницу (проверить: Pixi рисует в canvas,
   Chromium снимает — если потребуется, сохранить `preference: "webgl"` и/или резервную
   `toDataURL`-нарезку в tools/shots).
5. Критерий «замена готова»: снимки 2D-двора из `shots` выглядят не хуже 2D-прототипа,
   стройка/перестановка/ночь работают, `pnpm typecheck && pnpm test && pnpm build` зелёные.

Риски:

- PixiJS 8 молод (WebGPU-по умолчанию) — зрелость компенсируется 48k звёзд и v8.22;
  при проблемах — опция `preference: "webgl"`.
- Nочной слой/свет — в прототипе это просто img поверх; в Pixi — тот же приём
  (контейнер + blend/фильтр).
- Tiled-плагин для Pixi староват (2022) — не критично: двор маленький, TMX можно не вводить
  вообще, а в карту — решить к шагу карты.

## Решено (08.10.2026, заказчик)

- Xnova — рассмотрен, переносить нечего (DOM-таблицы, сцены нет); заимствуем идею
  Rust-движка боя для шага боёв и практику AGENTS.md.
