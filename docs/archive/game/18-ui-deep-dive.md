# Детальный разбор реальных UI партии 2

**Задача:** подготовить воспроизводимую спецификацию интерфейсного поведения для TDL — не копировать чужие логотипы,
лицензионный арт и точный skin. Анализ опирается на реальные игровые кадры из [галереи](17-ui-real-screens.md),
а не на store-креативы.

## Как читать заметки

- **Видно** — элемент/надпись непосредственно присутствует на игровом кадре.
- **Источник говорит** — поведение описано разработчиком/гайдом, но не проверено мною в живом клиенте.
- **Вывод** — интерпретация структуры UI; помечается отдельно от факта.
- **Не установлено** — данных нет. Размер в пикселях, зона касания, текущая версия клиента и анимация не выводятся
  из картинки без исходного разрешения и живой проверки.

Подробные кадры и ссылки: [галерея фактического UI](17-ui-real-screens.md). Точные версии старых скриншотов не
указаны; версия текущего приложения сама по себе не делает старый скриншот актуальным.

Subordinate City в галерее. **Свежесть:** средняя-низкая — это не клиент 2026.

| Узел | Что видно | Значение для воспроизведения | Уверенность / пробел |
|---|---|---|---|
| Сцена | Изометрический город; выбранный объект остаётся в контексте городской сцены. В обучающем кадре поверх него крупно показан персонаж и диалог. | Сцена продолжает давать контекст, когда поверх появляется объяснение или действие. | Статичный кадр; вход/выход из диалога не наблюдался. |
| Диалог | Имя персонажа вынесено в отдельную короткую шапку; текст расположен в нижней панели; справа у панели заметен маркер продолжения. | Персонаж, реплика и действие продолжения визуально должны быть разными уровнями. | Высота панели, безопасная область и кнопка «пропустить» не установлены. |

| Визуальная иерархия | Город — зелёно-серый; панель — тёмная/бронзовая; зелёный у действия, красный у риска. | Цвет используется как семантика состояния, не только как украшение. | Палитру и форму чужой игры не переносить как стиль TDL. |

### Экран B — состав марша

**Доказательство:** BlueStacks, guide от 21.01.2024; сборка игры неизвестна. Скриншот захвачен в эмуляторе:
рамка/панель BlueStacks вокруг телефона — не часть приложения.

**Порядок визуальных зон сверху вниз:**

1. **Шапка `March`:** круглая кнопка возврата слева, центрированный заголовок на бордово-красной плашке с золотой
   рамкой.
2. **Пресеты:** отдельная строка `Select a Preset`; шесть круглых слотов, в кадре слоты закрыты замком. Это состояние
   доступности пресетов, а не декоративные точки.
3. **Генерал:** одна широкая карточка на бронзовой подложке: круглый портрет, `Main General`, имя `Linn`, `Lv 1`,
   сила `3.9K`, кнопка-лупа справа.
4. **Типы войск:** каждая строка содержит портрет типа, название (`Warriors`, `Slinger Conscripts`), минус,
   горизонтальный ползунок с зелёным заполнением и синим маркером, плюс и числовое поле. В этом кадре выбрано
   230 Warriors и 200 Slinger Conscripts.
5. **Итог состава:** перед нижними действиями сгруппированы вместимость `430/800`, сила `3,900`, время `00:02:09`
   и ещё один числовой/ресурсный индикатор `100/0`. Последнее значение и его смысл по одному кадру не трактую.
6. **Действия:** две крупные кнопки в одном нижнем ряду — зелёная `Reset` и золотая `March`; на `March` виден
   дополнительный таймер `00:00:31`. Это часть состояния кнопки, но что именно отсчитывает этот таймер — без
   последовательности кадров не установлено.

**Что это даёт функционально:** экран сводит в одном месте состав/генерала/силу/время до отправки и действие
подтверждения. Числа рядом с ползунками дают точную настройку, а итоговая полоса показывает цену выбранного
состава до отправки. Это вывод из структуры кадра, не собственный тест реакции интерфейса на касание.

**Что нельзя повторить по снимку:** реальную ширину touch-target, шаг ползунка, пересчёт силы/времени, min/max,
перетаскивание, звук кнопки, disabled/pressed состояния, появление подтверждения и переход на карту. Эти пункты
нужно снять видео текущего клиента.

доступный raw-файл или захват актуального клиента, проверить его происхождение/версию и только после этого разбирать пиксели.
История версий приложения не связывает автоматически дату asset с точной сборкой клиента.

Это существенное различие не косметический toggle. |

**Числа, читаемые в кадре (пример конкретного сохранённого пресета, не игровая константа):** Turrets — Available 113,577 / поле 113,577; Heavy Lancer — 67,919 / 34,997; Champion Crossbowman — 4,258 / 1,350; Unsullied — 5,810 / 3,889; Reinforced Trebuchet — 44,377 / 25,761. Их важно сохранить при разборе изображения как фактические значения состояния, не использовать для баланса или расчёта лимита.

**Вывод для реализации:** здесь особенно сильна связка **доступно / выбрано / лимит / единица измерения**. Если в TDL
есть presets, нужно отдельно проектировать state `absolute count` и `relative percent`, валидацию сумм и эффект
изменившегося лимита марша. Нельзя выводить поведение ошибочного состояния из одного кадра.

### Экран B — Arena, актуальный игровой цикл 2026

**Доказательство:** [официальный Arena Overview](https://www.gotconquest.com/news/2026/05/20/arena-overview/) от 20.05.2026;
release notes 2026_08. Это самый актуальный функциональный источник GoT в партии. Картинки разработчика связаны в
галерее, но CDN не отдал оригинальные файлы в среду анализа; поэтому здесь разбираю подтверждённый текстом flow,
не приписываю пиксельные детали, которые не смог проверить, и не вывожу из статики длительность анимации.

**Поток состояния по официальному описанию:**

`здание Arena в городе → выбор нового/повторного lineup → потратить Sponsor → timed PvE-бой → урон добавляется к месячному рейтингу → результат/награда`.

- Бой происходит **внутри Arena**, а не на overworld map: нет марша и времени подхода.
- Враг появляется по заданной ротации; задача — нанести максимум урона до конца времени.
- Рейтинг учитывает суммарный урон за период; при равном результате выше тот, кто первым достиг значения.
- Потерь войск нет, лечить войска после режима не нужно.
- Sponsors генерируются Arena каждую неделю; они не переносятся за конец месячной дуги, а остаток конвертируется.
- Важные контексты UI: текущий противник/ротация, таймер боя, накопленный урон, доступность Sponsor, месячная граница,
  личный и allegiance leaderboard, награды.

**Свежая UI-правка:** release notes 2026_08 сообщают, что Event panel показывает количество March Items
(например Dragon Glass) непосредственно во время релевантных событий; доступ к этому количеству не требует открытия
Attack panel/Inventory. Патч также исправляет отображение/доступ к сведениям о March Pawns. Это уже конкретный
пример сокращения навигации, подтверждённый разработчиком.

**Что ещё нужно увидеть в raw capture:** бой до/после истечения таймера, переход между врагами, экран Sponsors,
состояние нулевого Sponsor, leaderboard, результат tie, claimed/expired reward и видимость текущего HP/урона.
Официальная страница даёт текстовую механику; сопровождающие CDN-изображения не удалось визуально проверить в этой
среде. Они не подтверждают пиксельные детали или саму последовательность взаимодействий.

## 3. State of Survival

### Экран A — поселение и сюжетный слой

**Доказательство:** BlueStacks review от 18.01.2024, версия клиента не указана. На сохранённом кадре видна рамка BlueStacks 4.18.0.1004; её заголовок, боковые инструменты и окружающее окно — не интерфейс игры и не часть phone safe-area.

- Основа кадра — изометрическое поселение с собственной глубиной объектов; интерфейс не вытесняет игровую сцену.
- Персонажный/диалоговый слой занимает заметное место поверх сцены; реплика помещена в отдельную нижнюю панель.
- Верхний HUD и быстрые входы должны читаться отдельно от сцены, но один сюжетный кадр не показывает их полный
  список или постоянное положение во всех режимах.
- `Skip` в кадре/описании подтверждает возможность пропуска диалога; не подтверждает, что весь onboarding можно
  пропустить целиком.

**Вывод:** нужно различать как минимум `scene only`, `character dialogue`, `selected building` и `construction/action`
состояния. Нельзя оставлять массивную реплику поверх кнопки действия, если именно она блокирует следующий шаг.

### Экран B — Explorer Trail, превью этапа до боя

**Доказательство:** BlueStacks guide от 19.01.2024, версия клиента не указана. В [галерее](17-ui-real-screens.md)
разведены два реальных состояния: Challenge 8 без guide-стрелки и Challenge 6 с красной стрелкой/рамкой,
добавленными автором guide (эти отметки не часть UI).

**Trail 2 Challenge 8 — что видно на чистом кадре:**

1. **Верхняя строка:** название `Trail 2 Challenge 8`; счётчик `100/100`, кнопка `+`, интервал восстановления
   `(1/600 sec)` и `X` закрытия.
2. **Левая панель угрозы:** вертикальный бейдж `Lv.VII`, `Squad Power 144,836`, крупное изображение заражённого,
   traits `Bone Armor` и `Rage`; внизу — последовательность из круглых маркеров.
3. **Правая панель состояния:** красная сетчатая полоса `Exploring`; ниже нарратив `The road to hell is paved...`
   с отдельно подсвеченным красным `Infected`.
4. **Gate и прогресс:** `Requires Hero Precinct Level 7`, затем `EXP Reward 212`.
5. **Награда:** горизонтальный ряд `Possible Rewards`; квадратные карточки с цветными рамками, предметом/иконкой,
   количеством и лентой `1st Time!` на части наград.
6. **Коммит:** крупная зелёная `CHALLENGE` внизу; на этом кадре цена попытки на кнопке не подписана.

**Trail 2 Challenge 6 — отдельный кадр, частично аннотированный guide:**

- Верх: `100/100` ресурса попытки, плюс и `(1/600 sec)`; слева показано `Squad Power 117,918` в панели этапа/противника. Точный смысл поля отдельно не подписан, поэтому сохраняю его как видимую метку, не как норму/порог.
- Справа: `Your Squad Power 198,182`, три портрета героев с уровнями 23/20/23, типовыми иконками и небольшими
  маркерами у карточек.
- Карточка противника показывает `High Health` и `Summoning Ability`; текст этапа, `Requires Hero Precinct Level 6`,
  `EXP Reward 208` и ряд возможных наград.
- Нижняя зона содержит `Prediction: Walkover` и кнопку `CHALLENGE` с расходом 15 единиц энергии.
- Красная рамка и крупная стрелка на изображении — **авторская разметка BlueStacks**, поверх реального игрового кадра.
  Не переносить её в макет; отмеченный ею ряд маркеров требует отдельной проверки в клиенте.

**Поведение, описанное BlueStacks guide:** tap по узлу Trail открывает превью до выхода на поле; на левой модели врага
можно прокручивать список встречающихся противников. Источник описывает это как drag/cursor interaction в эмуляторе;
точный мобильный жест и инерция не проверены.

**Функциональная логика:** до начала этапа интерфейс собирает в одном месте угрозу, условия, состав/силу своей команды
(во втором кадре), прогноз, цену попытки и ожидаемую добычу. В TDL это кандидат на предбоевой decision card;
нужно различать `hard gate` (не выполнено требование уровня), `estimate` (Walkover/риск) и `cost` (энергия) как три
разные семантики.

**Не установлено:** мобильные touch-targets, подсветка выбранного врага в прокручиваемом списке, точность/объяснение
`Prediction`, disabled-поведение кнопки, изменение цены, состояние без наград, автоповтор/sweep, последовательность
после `CHALLENGE` и переход к экрану результата. Красная стрелка guide не является доказательством интерактивного
фокуса игры.

### Текущая версия — что меняется в меню

Официальный [патч 1.26.900](https://stateofsurvival.game/en/blog/1165) от 12.09.2026 — это источник поведения UI,
а не новый набор скриншотов:

| Изменение | Подтверждённая роль интерфейса | Что нужно снять для TDL |
|---|---|---|
| Batch Hero Search | Повторяющийся поиск/получение героя поддерживает пакетную операцию. | Количество, прогресс, empty/error, отмена и итоговый reward state. |
| Completed Intel наверх | Приоритетная сортировка завершённых задач сокращает поиск награды. | Положение active/completed/claimable, обновление списка после claim. |
| Event lineup под `More` | Порядок и группировка событий в меню изменены. | Число уровней навигации, badge, таймер, сохранение позиции. |
| Skip Becca before PvP | Реплика перед PvP может быть пропущена. | Различие skip-one/skip-all и блокировка кнопок на старте боя. |
| Highlight troops in Alliance Rally | Свои войска легче найти в списке rally. | Цвет/значок владения, сортировка и доступность при длинном списке. |
| Material count in Research Lab | Видно, сколько нужного ресурса уже есть. | Доступно/не хватает, стоимость, переход к источнику предмета. |

## 4. Lords Mobile

### Экран A — герой и источник медалей

### Детали, которые ещё нельзя специфицировать честно

1. **Геометрия:** реальные координаты, safe-area/insets, DPI и минимальные касания — в источниках нет калиброванных
   screenshot-файлов исходного разрешения.
2. **Состояния:** disabled, pressed, loading, empty, cooldown, ошибки сети/оплаты, частичное получение награды.
3. **Динамика:** сколько длится появление панели, затемнение, перелистывание героя, открытие сундука, обновление числа;
   есть ли hit-stop, camera shake, частицы, подсветка/контур цели.
4. **Звук/хаптика:** не следует сочинять по статике или по рекламному ролику.
5. **Актуальность:** у нас есть текущие патчи/официальные описания, но не текущий raw capture всех экранов.
6. **Локализация:** размер строк/переносы на русском и английском не проверялись на live UI.

## 6. Следующий проход, чтобы перейти от анализа к воспроизведению

Для каждой из четырёх игр захватить один и тот же набор, если режим доступен: **двор → выбранный объект → карта → цель →
состав войск → подтверждение → марш/бой → результат → герой/прокачка → событие/награда**. Для State отдельно записать
Explorer Trail, для Lords — Hero Stages, для GoT — Arena, для Evony — city/march и текстово описанный Event panel из patch notes (без свежего capture).

В протокол кадра заносить: `игра/версия → устройство/разрешение/orientation → raw screen → действие пальца → следующий state →
анимация/длительность → звук/хаптика → источник/таймкод`. Эмуляторные рамки удалять только если исходный экран клиента
сохранён отдельно; не «подчищать» игровые элементы.

**Решение для TDL:** после такого прохода можно делать нейтральный greybox с точными зонами, переходами и состояниями. Выбор
палитры, материалов, рамок, шрифтов и художественной подачи остаётся отдельным шагом и по этим референсам заранее не
фиксируется.
