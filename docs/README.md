# Документация TDL

Это входная точка во всю документацию игры. Если вы — новый ИИ-агент или новый человек в проекте, начните здесь и не читайте архив без необходимости.

## 1. Карта

| Что | Где | Зачем |
|---|---|---|
| Этот файл | `docs/README.md` | Архитектура, статусы, процесс работы |
| Состояние | `docs/STATUS.md` | Что решено, что описано, что реализовано в коде |
| Журнал решений | `docs/DECISIONS.md` | Каждое решение заказчика, с датой и причиной |

| Числа и баланс | `docs/balance/` | Числа по системам. Сейчас здесь `09-numbers` (на разборе, см. §5) |

## 2. Статусы

Статус ставится в шапке документа и в `STATUS.md`. Устаревшие документы сюда не попадают: они переезжают в архив, а не получают статус.

| Статус | Значение |
|---|---|
| **черновик** | Набросок. Не утверждён, нельзя опираться как на решение |
| **на обсуждении** | Ждёт решения заказчика. В документе явно перечислено, что открыто |
| **утверждено** | Решение принято и записано в `DECISIONS.md`. Код можно писать |
| **реализуется** | Код в работе |
| **реализовано** | В коде, проверено проверками и просмотром |
| **отложено** | Решено не делать сейчас. Запись остаётся в журнале |

Шапка документа:

```
> Статус: на обсуждении · Обновлено: 09.10.2026
> Решения: см. DECISIONS.md (даты) · Открыто: (список)
```

## 3. Журналы

**`DECISIONS.md` — журнал решений.** Одна запись на одно решение, новые сверху, с датой:
- что решено (одной-двумя фразами);
- почему, если причина важна;
- какие документы затронуты;
- статус: решено / открыто / отменено.

**`STATUS.md` — журнал состояния.** Матрица по системам: что решено, что описано, что реализовано, что открыто. Обновляется, когда решение утверждено или код сделан.

Правило: решение и правка документа идут **в одном коммите**. Не может быть решения в чате без записи, и не может быть записи без решения.

## 4. Процесс работы (обязательный)

1. **Обсуждение.** Вопрос сформулирован, варианты описаны с плюсами и минусами. Ничего не решается молча.
2. **Решение заказчика.** Ответ записывается в `DECISIONS.md` в тот же день.
3. **Документ.** Правится документ по теме, ставится статус, перечисляется открытое.
4. **Код.** Пишется только после статуса «утверждено». Код не меняет решения и не придумывает числа: числа берутся из документов `balance/`.
5. **Проверки.** Перед коммитом: `pnpm typecheck`, `pnpm test`, `pnpm check`, `pnpm build` (см. `AGENTS.md`). Тесты не оставляем красными: обновляем.
6. **Статус.** После кода обновляется `STATUS.md`.
7. **Коммит.** Сообщение по-русски. Коммит и push — после каждой правки в активной разработке, в сессионную ветку, без `--force`. Заказчик тестирует в Replit, поэтому пушим сразу.

Ответы других ИИ (сторонние разборы) — это вход для обсуждения, а не решение. Переносятся только утверждённые части.

## 5. Правила для ИИ-агента (передача между чатами)

Перед работой прочитайте по порядку:
1. Этот файл.
2. `docs/STATUS.md` — что сейчас в работе.
3. Последние записи `docs/DECISIONS.md`.
4. Документ по теме задачи (обычно `docs/design/...`).

Нельзя без явного запроса:
- писать код игры до статуса «утверждено»;
- удалять архив или что-либо из `docs/game/ui/`;
- возвращать отменённое (см. `DECISIONS.md`): 3D-направление, «Паутину», «Частокол», погреб, концепты skin, «Ратушу» как название главного здания;
- менять `packages/protocol` и серверную часть (правило `AGENTS.md`);

Названия пишутся по-русски так, как утверждено: Цитадель, Академия, Стена, Склад, Казарма, Лазарет, Пункт марша, Двор (территория, не здание).
