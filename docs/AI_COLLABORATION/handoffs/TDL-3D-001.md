## Цель

Дать владельцу проекта доказательное сравнение технических путей к полноценной 3D изометрической стратегии для mobile + browser/PC, не меняя production-клиент.

## Входит

- Изучить текущий репозиторий и ограничения PixiJS/React, server-authoritative state и asset pipeline.
- Сравнить минимум три варианта:
  1. сохранить текущий web app и добавить подходящий web-native 3D renderer;
  2. Three.js или Babylon.js как кандидаты (не считать ни один заранее выбранным);
  3. Godot с Web export как отдельный кандидат.
- Оценить mobile browser/touch, desktop browser, загрузку, FPS/frame-time, память, доступность инструментов, импорт glTF/PBR, освещение, тени, LOD, UI overlay, интеграцию с текущим backend, размер сборки, CI и сложность поддержки.
- Проверить актуальные ограничения/документацию каждого кандидата; дать ссылки на первоисточники и дату проверки.
- Предложить один и тот же минимальный benchmark-сценарий для честного сравнения.

## Не входит

- Не менять основной клиент и production зависимости.
- Не создавать массовую миграцию или удалять PixiJS.
- Не объявлять Godot/Three.js/Babylon.js утверждённым движком.
- Не менять протокол, сервер, БД, экономику или auth.
- Не считать красивый рендер достаточным доказательством работоспособности.
