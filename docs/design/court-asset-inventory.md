## 1. Геометрия действующей Pixi-сцены

Источник: `apps/client/src/game/court/isometric.ts`, `types.ts`, `courtScene.ts`, `tileMap.ts`.

| Параметр | Текущее значение | Следствие для арт-пайплайна |
|---|---:|---|
| Размер сетки по умолчанию | 14 × 14 клеток | Не путать размер доски с размером отдельного ассета |
| Tile width | 71.4 px | Горизонтальный шаг диметрической проекции |
| Tile height | 41.4 px | Вертикальный шаг диметрической проекции |
| W:H | ≈ 1.725:1 | Эталонный ромб клетки |
| Проекция | x=(X−Z)·W/2; y=(X+Z)·H/2 | Все asset pivots должны соответствовать одной системе |
| Центрирование | вертикальный сдвиг на size·H/2 | Камера центрирует доску |
| Камера | общий transform root-контейнера | Спрайты и hit regions должны жить в одной локальной системе |
| Слои | ground → roads → buildings → preview | Декор/terrain потребуют явной схемы глубины |
| Sorting зданий | maxX + maxZ | Нижняя граница footprint, не верхушка изображения |
| Hit testing | sprite bounds при загруженном sprite; vector fallback иначе | Прозрачные поля не должны чрезмерно расширять кликабельную область |

### Текущая отрисовка terrain

`tileMap.ts` рисует каждую клетку через Pixi Graphics: четыре варианта плоского цвета грунта, тонкая линия-кромка, общий контур доски. Дороги — уменьшенные ромбы с детерминированными точками-галькой. Отдельных runtime terrain-текстур, переходных тайлов, краёв/склонов и декора земли сейчас нет. Это главный визуальный пробел до нового комплекта.

## 3. Legacy prototype — что подтверждено, что расходится

Исходный prototype: `docs/game/ui/court/court.js` и atlas JSON в `docs/game/ui/court/sprites/`.

- Старый prototype задавал «keep» как 3×3, тогда как актуальный серверный catalog задаёт Цитадель 4×4.
- Старый prototype задавал склад 2×2, текущий catalog — 3×3.
- Старый prototype задавал лазарет 2×2, текущий catalog — 3×3.
- Старый prototype задавал загон 3×2, текущий catalog — 2×2.
- Старый `c-01` обозначен как «Паутина» (исследовательская постройка); текущий каталог содержит «Академию». Автоматическое равенство этих сущностей не подтверждено и mapping удалён.
- Старые night PNG не включать по локальному времени клиента. В `CourtState` нет authoritative world time/lighting state.
- Разные atlas family имеют различные габариты; нельзя переносить размеры одного sprite на другой.

Следствие: старые изображения годятся только для временной визуализации и проверки технического пути. При текущих footprints их визуальные подошвы могут не совпадать с серверным занятым пятном; это ещё один аргумент не считать их финальным артом.

## 4. Asset production schema (предлагаемый контракт)

Каждый новый объект должен иметь запись с полями:

- `assetId`, `kind`, `sourceFile`, `license`, `sourcePromptOrBrief`;
- `logicalWidth`, `logicalHeight`, `footprintW`, `footprintH`;
- `anchorX`, `anchorY`, `footprintPatchWidth`, прозрачные поля;
- `renderLayer`, `depthAnchor`, `hitRegion`;
- `states` (base / selected / construction / upgrade / damaged — только реально поддерживаемые состояния);
- `fallbackAssetId`, `format`, `compression`, `fileBytes`, `textureBytesEstimate`.

Не вводить визуальные состояния, не поддержанные игровой логикой. Для зданий уровни сначала группировать в несколько художественных эпох/tiers только после согласования с балансом и игровым прогрессом.

## 5. Terrain vertical slice — состав

Минимальный эталонный фрагмент:
1. Базовый tile set с бесшовными стыками и вариациями без заметного повторения.
2. Один переход грунт ↔ трава/камень и корректный край доски.
3. Один участок дороги, который сохраняет стыки при поворотах и пересечениях.
4. Hero asset Цитадели, привязанный к footprint 4×4.
5. Два разных здания из каталога с footprint 2×2 и 3×3.
6. Небольшой набор props с проверенными footprint/depth anchors.
7. Проверка выбора и попадания по видимой части объекта, а также fallback при отказе загрузки.
