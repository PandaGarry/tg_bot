| Что | Решение | Статус |

| 3D в целом | не используем | решено 09.10 |

Почему PixiJS, а не Phaser:
- PixiJS — рендерер, а не хозяин экрана. React остаётся хозяином HUD; сцены живут в `<canvas>` внутри разметки.
- Для двора до 20×20 и карты физика, сцены и TMX-обвязка Phaser — лишний вес.
- PixiJS 8 покрывает нужное из 3D-двора: спрайты, глубину (сортировка по диметрии), пан и зум, blend-режимы для ночи, частицы.
- Solaris — 4X на PixiJS и Node в продакшене.

Почему не готовая игра целиком: чужой стек и протокол дороже, чем сцена спрайтов поверх прототипа `docs/game/ui/court/`, где уже решены клетка↔мир, глубина, камера и стройка.

Отклонено: Unity (проприетарный, платный веб, редакторный воркфлоу); Godot (сейчас не проверить в нашей среде; может понадобиться позже, если нужен движок-хозяин); @pmndrs/uikit (3D-UI для R3F, от которого уходим).

## 2. Риски (предложено)

- PixiJS 8 молод (WebGPU по умолчанию). Компенсация — 48k звёзд, v8.22; при проблемах — `preference: "webgl"`.
- Ночной слой: прототип делает его просто картинкой поверх; в Pixi — тот же приём (контейнер и blend или фильтр).
- Tiled-плагин для Pixi староват (2022). Для двора TMX не нужен; решить к шагу карты.

## 3. Спайк (предложено, не начат)

1. В `@tdl/client` убрать `three`, `@react-three/fiber`, `@types/three`; добавить `pixi.js`. Приложение `court3d` отцепить, `main` не трогать.
2. `src/court/PixiCourt.tsx`: canvas внутри текущей разметки. Диметрическая сетка (формулы — из прототипа), здания — спрайты из PNG (конвейер `pnpm icons`), сортировка по глубине, пан и зум, призрак в стройке, выбор. Данные — из того же view и патчей; сервер не трогаем.
3. Связь HUD и сцены — через существующий `store.ts`.
4. `pnpm shots` должен снимать страницу с canvas. Если нужно — `preference: "webgl"` или резервная `toDataURL`-нарезка в `tools/shots`.
5. Критерий «замена готова»: снимки двора не хуже 2D-прототипа; стройка, перестановка и ночь работают; `pnpm typecheck && pnpm test && pnpm build` зелёные.
