# Сцена двора: конструктор, камера, время суток, поры года, стадии

> Статус: **предложено** (сцена — конструктор; геометрия и камера — предложены, не утверждены) · Обновлено: 14.10.2026
> Источники: прототип сцены в `docs/game/ui/court/` (круг 7, 27.09.2026) и предложения раунда 6 (`archive/game/22`, `archive/game/23`, перенесены 14.10). Решения — [DECISIONS.md](../DECISIONS.md).
> Связано: раскладка HUD — [hud-court.md](hud-court.md) (§0б — схема зон); данные зданий — [buildings.md](buildings.md); календарь пор года — `design/calendar.md` (очередь архива, `11-calendar`).

Термины: **Двор** — территория и экран. **Цитадель** — центральное здание (в старых прототипах — «Двор» или «Ратуша»; это то же здание, название — Цитадель).

## 1. Принцип

- Интерфейс (рамки, кнопки, иконки, плашки) не меняется ни от времени года, ни от времени суток. Меняется **сцена**: земля, фон, здания, свет.
- Сцена — не одна картинка. У каждого игрока свой двор: сервер хранит состояние, клиент собирает картинку из слоёв.
- Состояние двора (сервер → клиент), пример:

```jsonc
{
  "size": 14,                                              // клеток по стороне (предложено)
  "look": { "season": "winter", "time": "night" },         // пора — из календаря; время — см. §5
  "wall": { "level": 3 },                                  // Стена — отдельное здание, стадии по уровню
  "buildings": [
    { "id": "citadel", "type": "citadel", "level": 7, "x": 3, "y": 3 },
    { "id": "sawmill1", "type": "sawmill", "level": 6, "x": 7, "y": 2, "pin": "collect" },
    { "id": "wh1", "type": "warehouse", "level": 1, "x": 7, "y": 6, "building": { "until": 1790000000 } }
  ]
}
```

- Действия игрока — три команды: `place(type, x, y)`, `move(id, x, y)`, `upgrade(id)`. Клиент проверяет их локально (границы, пересечения, стоимость) ради отзывчивости; окончательно решает сервер и присылает новое состояние.
- Каталог типов (имя, след, спрайты, точка опоры) — общий справочник, рядом с данными зданий в [buildings.md](buildings.md).

Слои снизу вверх (всё, кроме HUD, — в одном контейнере, которым двигает камера):

1. Земля — площадка с окрестностями по поре и времени суток.
2. Сетка (только в стройке) — линии по углам клеток, двухцветные: читаются и на снегу, и на земле.
3. Следы — ромбы занятых клеток; зелёный/красный след призрака.
4. Здания — спрайты по глубине; у каждого дневная и ночная картинка.
5. Призрак — переставляемое или новое здание, полупрозрачный, с ✓/✕.
6. Подписи и пины (таймер стройки, «забрать», «улучшить») — в прототипе внутри мира; в клиенте лучше в слое экрана.
7. HUD — не двигается и не масштабируется с камерой.

## 2. Геометрия: ортографическая диметрия (предложено)

- Площадка — ромб 14×14 клеток (196). Предложен запас под все типы зданий и украшения; число клеток пока не сверено с footprint из `buildings.md`.
- Клетка — ромб `W×H = 71,4×41,4` px мира (≈1,72:1, камера ≈35° над горизонтом). Ось *x* — вправо-вниз, *y* — влево-вниз.
- Клетка `(i, j)` → мир: `sx = TOPx + (i − j)·W/2`, `sy = TOPy + (i + j)·H/2`. Обратно (палец → клетка): `u = (wx − TOPx)/(W/2)`, `v = (wy − TOPy)/(H/2)`, `i = (u+v)/2`, `j = (v−u)/2`, затем `floor`.
- След здания `(x, y, fw, fh)`: углы `(x,y) (x+fw,y) (x+fw,y+fh) (x,y+fh)`. Нижний угол `(x+fw, y+fh)` — точка опоры спрайта.
- Спрайт масштабируется так, чтобы ширина подошвы стала шириной следа `(fw+fh)·W/2`, и ставится нижним углом подошвы на нижний угол следа. Один спрайт встаёт в любую клетку одинаково — поэтому перспективная подложка уходит.
- Порядок отрисовки — по сумме `x+fw+y+fh`; при равных — по `x+fw`. Для длинных зданий (Стена) понадобится топологическая сортировка.

## 3. Камера (предложено)

- Весь мир — один контейнер с `transform: translate(tx, ty) scale(z)`.
- Панорама — перетаскивание пустого места. Зум — колесо, щипок (вокруг середины пальцев), двойной тап (×1,5). Пределы `z ∈ [0,85; 2,2]`; край площадки не показывает пустоту.
- Обычный режим: `z = 1`, площадка целиком с лесом вокруг.
- Стройка: отъезд до `z ≈ 0,86` так, чтобы площадка была целиком в зоне, свободной от панелей.
- Первый день: камера может стартовать ближе (`z ≈ 1,2`).

**Почему не наклонная камера.** В RoK камера наклоняется в стройке, потому что там 3D. У нас 2D-спрайты: у каждого здания один ракурс. Удобство стройки даёт ортографическая сетка: все клетки одинаковы на всём экране, здания не закрывают клетки сильнее, чем в RoK. Перспективная сетка (прежний круг 5) была неудобной, её сняли.

Варианты, которые не предлагаем: второй набор спрайтов «сверху» (удвоение ассетов); 3D-двор (**отменено 09.10.2026**, не используется). Рекомендация прототипа: оставить ортографический ракурс ≈35°, стройка = отъезд + сетка.

## 4. Стройка: сценарии (предложено)

| Шаг | Что видит игрок |
|---|---|
| «Строить» | Камера отъезжает, сетка и следы включаются, снизу карточки по вкладкам: Экономика · Военные · Украшения |
| «Поставить» на карточке | Призрак на ближайших свободных клетках у центра экрана, над ним ✓ и ✕, след зелёный |
| Тянем призрак | Клетка считается из положения пальца минус смещение захвата — здание не прыгает под палец. Красный след — место занято |
| ✓ | Здание в состоянии «стройка»: леса по размеру следа, подпись «Склад · 12:40» с полоской |
| Готовое здание, схватить | Становится призраком; на старом месте остаётся бледная копия |
| Обычный режим, тап по зданию | Подсветка и пузырь «Улучшить · Переставить · Инфо» |
| Тап по пустому месту | Снять выбор |

Счётчик свободных клеток в заголовке стройки считается из следов. В игре добавятся: лимит зданий типа («1 / 2»), уровень Двора, ресурсы и очередь строителя.

## 5. День и ночь (предложено, не решено)

- Четыре состояния: утро 6–10, день 10–17, вечер 17–22, ночь 22–6. Начать можно с двух (день и вечер).
- Время — **по часам устройства** игрока, чтобы за окном и на экране было одно время. Серверное время мира остаётся для календаря и окон дня.
- В настройках: «как за окном / всегда день / всегда вечер».
- Зимой темнеет раньше: границы сдвигаются по поре (таблица из четырёх строк, без астрономии).
- Переход — кроссфейд 2–3 с; при длинной сессии — медленный закат за минуту.
- Реализация: фильтр яркости и насыщенности, синий multiply-слой, подъём теней в синий, слой огней (окна, очаг, факелы).
- Экономия ассетов: ночь = дневной спрайт × синяя градация + слой огней (только маски окон). В прототипе есть раздельные день и ночь файлы; переход на слой огней — оптимизация этапа C.

## 6. Поры года (предложено)

- Источник истины — модуль пор года календаря: включена ровно одна пора, признак на корне разметки (единица `look`). Есть «примерка» для QA.
- Меняется: фон, земля, лес (хвоя всегда; берёзы — листья / жёлтые / голые), река (лёд / вода), снег на крышах и стене зимой, частицы, время заката.
- Не меняется: интерфейс, иконки, размеры и позиции.
- Здания: два набора — «в снегу» и «без снега». Весна, лето и осень отличаются землёй и лесом, не крышами.
- Интерфейс не сезонный; акценты событий (снежинка на плашке ивента) — отдельная тема HUD.

## 7. Стадии зданий (предложено)

- Пять стадий. Предложенные границы по уровню: I — 1–4, II — 5–9, III — 10–15, IV — 16–20, V — 21–25 (по образцу эпох RoK). **Не решено** заказчиком; сверить с 30-уровневой шкалой из [buildings.md](buildings.md).
- Стадия здания — по его уровню. Стадия Стены и «богатство» фона (пропсы, люди) — по уровню Цитадели.
- Footprint внутри и между стадиями не меняется: здание растёт вверх и «в детали».
- Каждая стадия читается силуэтом на дальней камере: I — времянка, II — крепкое, III — второй объём или пристройка, IV — появляется камень, V — символ (шпиль, знамя, резьба, дым).
- Уровень внутри стадии показывается цифрой на пине или в карточке, не картинкой.

## 8. Растущий двор (предложено)

- Первый день: Цитадель I, один сарай, кривой тын по тому же периметру, пни и сугробы, три жителя. С первого дня стоят Цитадель и Стена с воротами; остальное игрок ставит сам (решено 27.09 для круга 7, сохранено).
- Периметр фиксирован с первого дня, расти будут Стена и плотность, а не площадь. Альтернатива (расчистка участков) не предлагается.
- Пустые клетки — земля с редкими пнями или камнями; при постройке декор исчезает.
- Тропинки протаптываются автоматически от ворот к зданиям (слой между землёй и зданиями).
- Камера в начале ближе, по мере заполнения двора отъезжает.

## 9. Ассеты (предложено)

- Генерация **листа** на пурпурном фоне (#FF00FF): 3 здания в ряд, одна камера, дневной свет, референс — подложка круга 5. Затем правка того же листа под ночь (окна горят, фон не трогать): геометрия совпадает пиксель в пиксель.
- Нарезка: `pnpm icons court/sprites/sheet-a.png --prefix a --pad 4 --merge-gap -1` — хромакей, связные пятна, PNG с прозрачностью.
- В каталоге — `patch` (ширина подошвы) и `tip` (нижний угол подошвы), пока вручную; резак сам найдёт подошву (следующий шаг).
- Правило стиля: новые здания — **правкой существующего листа**, не с нуля.
- Сделано: 11 спрайтов × день и ночь (Цитадель, Лесопилка, Каменоломня, Ферма, Загон, Склад, Казарма, Лазарет, Пункт марша, Паутина, Стройка) + земля день и ночь. Это стадии I–II. Стадии III–V — тем же конвейером.
- Оценка объёма (предложено): здания × 5 стадий × 2 набора + огни + стена + пропсы ≈ 270 картинок. Вес: webp, атласы, догрузка только текущей поры и открытых стадий.

## 10. Этапы и открытые вопросы (предложено)

Этапы (предложены):
- **A.** Решения и библия стиля: ответы на вопросы ниже, таблица зданий с footprint, камера. Проба — 3 здания × 2 стадии в ортокамере на двух порах и двух временах.
- **B.** Вертикальный срез: Цитадель и Стена во всех стадиях, земля зимы и лета, свет день и вечер, первый день → двор 25.
- **C.** Полный набор: все здания × стадии × наборы, огни, пропсы, тропинки, весна и осень.
- **D.** Полировка: анимация (дым, флаги, люди), погода, утро и ночь, акценты событий.

Нерешённое (заказчик):
1. Ракурс ≈35° и ортографическая сетка вместо перспективной подложки — принять как производственный стандарт?
2. Площадка 14×14 с фиксированным периметром — ок?
3. Время суток: по часам устройства; два состояния (день и вечер) или четыре?
4. Границы стадий I–V — подтвердить или заменить.
5. Перестановка: в стройке — сразу тянуть; в обычном режиме — тап → «Переставить», или добавить длинное нажатие?
6. Погода (снег, листья): делать в этапах C и D или не делать.
7. Список типов зданий и footprint — сверить с [buildings.md](buildings.md) (18 зданий + Цитадель, решено 10.10).
